# 改写式实现相似度复核

本轮 M3 针对功能评测中的已知漏报：付费模块另写权限过滤、金额校验和 CSV 编码，更换局部变量、循环和字符串拼接方式后，连续 token 检测可能仍为零。现在 check 增加 POSSIBLE_DUPLICATION，给出可解释的共有证据，状态为 needs-review。它提示检查职责重叠，不证明语义等价或要求合并。

## 当前边界与证据

算法标识为 implementation-anchors/1。复用 indexSources 已有 TypeScript AST，仅 check 请求提取实现资料；context 默认不执行此步骤，也不做额外扫描或模型调用。

- 处理已有符号索引支持的具名函数、变量函数和方法，函数块至少包含四条直接语句；匿名回调中的操作可归于外层函数，独立具名的嵌套函数、对象方法和类表达式方法分别分析，不把方法体重复计入外层工厂。
- 保留字符串/无插值模板的实际值（6–120 个 JS 字符单位）、数据属性名、成员操作名。局部变量及控制流形状不作为共有证据；直接 throw、console 调用、类型、注释和常用数组管道操作不提供匹配依据。
- 两侧各至少有一个字面量、三个数据属性、两个成员操作、共八个锚点。配对必须共有至少一个字面量、三个属性、两个操作及八个锚点，且覆盖较小一侧至少 65%。这些是保守启发式条件，不是普遍语义阈值。
- 不解析接收者类型、操作绑定或调用参数，也不能证明字面量一定流入输出。独立职责、不同授权或格式要求仍可能出现相似证据，需结合需求审查。

按同文件/符号身份，再按去注释和打印规范化后的完整函数体做一对一基线匹配。原有配对的共有证据已覆盖当前证据时不再提示；迁移不凭空增加实现数，一个旧实现也不能匹配任意多个新副本。新增配对或共有证据扩大时进入复核；同一函数对已有 NEW_DUPLICATION 时不重复提示。

## CLI 与报告

新增顶层 similarityAlgorithm、possibleDuplications，分别标识规则版本和可能重叠的函数对数。newDuplications 继续只计原有精确 token 序列组，attributionAlgorithm 仍为 token-occurrences/1，两类数量不能相加当作已证实重复。

每条 POSSIBLE_DUPLICATION 含两个函数的位置和 similarity：algorithm、shared（literals/members/calls）、sharedAnchors、leftAnchors、rightAnchors、evidenceTruncated。各 shared 列表按序最多显示 20 项；计数为截断前总数，evidenceTruncated 表示证据列表存在删节。原有 token 归因仍使用 attribution；可能重叠不伪造出现次数或作者归因。

该规则始终 severity: review，duplicatePolicy: fail 仅沿用精确 token 规则的失败策略。测试失败、清理失败或执行错误仍按原优先级返回。summary 保留这些发现和证据，完整报告仍写入 report.json；所有配置的验证照常执行，无结果缓存或新增跳过选项。

复用或抽取后只剩一份实质实现、其他入口作薄委托时，该配对不再出现。若不同职责确需保留相似实现，应审查并说明差异；重复执行未变化的测试不会消除提示。本轮不增加例外审批或自动合并机制。

## 验证与限制

[回归测试](../test/similarity.test.mjs) 复现原有改写式复制：相同业务验收通过、新增 token 重复仍为零，新增一条复核提示；改成委托已有 exporter 后恢复 pass，两种实现均运行全部配置测试。另覆盖八种 JS/TS 后缀、实际 JSX、计算属性、变量函数、类方法、跨业务字段替换、历史配对、移动、额外副本、共有证据扩大、诊断与注释、独立通知及权限职责。

在独立目录恢复上一轮十二份实际 agent 补丁的相同基线，再用新 check 重放，全部仍为 pass、possibleDuplications 为 0，完整三个运行时验收文件通过；原始会话与报告未覆盖。此为确定性重放，没有新模型会话或改善比例。

这一步覆盖已知反例的一类改写，不保证发现所有职责重复。短函数、表达式函数、没有共同有效字面量/成员操作、字段全面变化、间接调用，以及净数量相同的删除再新增等仍可能遗漏。具名身份及规范化函数体匹配不是语义身份。大规模同锚点函数集合的候选配对与一般误报率仍需评测。
